One dashboard

Websites are more than uptime.

A site can return HTTP 200 and still be broken. Web Fleet is designed to understand the website itself, not just whether a server responds.

Availability

HTTP status, latency, redirects, failures, recoveries and incident history.

TLS and DNS

Certificate expiry, hostname validity, DNS resolution and meaningful configuration changes.

Pages and links

Crawl sites, find broken internal links and surface regressions without turning every check into noise.

Performance

Track response behaviour over time and make regressions visible across the fleet.

Analytics

Optional, privacy-first traffic analytics for static sites, VPS-hosted apps and everything between.

Incidents

Turn repeated failures into coherent incidents with recovery history instead of alert storms.

Start simple

One binary. One database. Add a URL.

The default deployment is intentionally small: Web Fleet plus SQLite. Monitoring works without changing the site being monitored.

Analytics is opt-in. Add a lightweight tracker only to the sites where traffic insight is useful.

# Planned installation flow
curl -fsSL https://web-fleet.github.io/install.sh | sh

webfleet serve

Scale without replacing it

For one site, a client portfolio, or a large web estate.

The small installation stays understandable. Larger deployments can add PostgreSQL, users, organizations, RBAC, SSO and separated workers without turning those into prerequisites for everyone.
