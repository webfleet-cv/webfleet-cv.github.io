Core features

Website health

After reliable uptime checks, Web Fleet expands into the things that make a website healthy even when its server still returns 200.

TLS

Observe certificate validity, hostname matching and expiry. Fleet-wide warnings should make expiring certificates visible before they become outages.

DNS

Record relevant resolution results and surface meaningful changes. History matters: the useful question is often not just "what does this resolve to?" but "when did it change?"

Pages and links

A bounded crawler can discover pages and internal relationships, then report new broken links as regressions. External links need more conservative scheduling and rate limits than internal checks.

site crawl
├── /                  200
├── /docs/             200
│   ├── /docs/install  200
│   └── /docs/api      404  ← new regression
└── /download          301 → /releases

Headers and redirects

Web Fleet can observe response/security headers and redirect chains without pretending every optional header is universally mandatory. Expectations should remain configurable and contextual.

Performance

Server-side timings and transfer behaviour come first because they can be measured cheaply and consistently. Browser performance checks may be added later, but Web Fleet should never label synthetic server timing as Core Web Vitals.
