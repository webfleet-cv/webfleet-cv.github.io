Getting started

Web Fleet is in early development. These docs establish the intended operator experience and architecture while implementation catches up.

Current status: there is not yet a public Web Fleet release to install. Commands on this page marked as planned describe the target first-run experience rather than a shipped installer.

The five-minute goal

A normal self-hosted installation should eventually require three steps: install Web Fleet, create the first admin, and add a website URL. Public monitoring should begin without an agent or code change on the monitored website.

# Planned installation flow
curl -fsSL https://web-fleet.github.io/install.sh | sh
webfleet serve

Open the dashboard, complete first-admin setup, then add a site such as:

Name:     Example
URL:      https://example.com
Interval: 60 seconds

What happens after adding a site

The first implementation milestones will schedule HTTPS checks, record status and latency, classify failures, and derive a fleet-level health state. Later checkpoints add TLS, DNS, crawling, performance and optional analytics.

Adding analytics later

Analytics is deliberately separate from public monitoring. A GitHub Pages site, static Nift site or application hosted on another provider can send pageview events to one central Web Fleet server.

<script
  defer
  src="https://fleet.example.com/tracker.js"
  data-site="site_public_id">
</script>

The planned default tracker does not require cookies or persistent visitor profiles.
